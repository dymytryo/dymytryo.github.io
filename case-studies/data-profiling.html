The analysis, cell by cell

The dataset is a synthetic merchant-contact extract that is messy on purpose — every defect was injected by a documented generator script, so the profile’s findings can be checked against ground truth. All names and contacts are fabricated.

Step 1 — first contact with the file

Before any tooling: how big is it, what does it look like, what did pandas guess for types?

Step 2 — targeted checks

The two questions worth asking any contact list up front: what’s missing, and who is in here twice?

Step 3 — the one-liner profile

ProfileReport computes per-column distributions, missingness patterns, duplicate detection, correlations, and cross-column alerts — and writes the self-contained interactive report embedded above.

generate the report + alert list 
profile = ProfileReport(
    df,
    title='Merchant Contacts - Raw Extract Profile',
)
profile.to_file('profile_report.html')

alerts = profile.description_set.alerts
for a in alerts:
    print(f"- {a}")
alerts raised: 10 - Dataset has 12 (0.6%) duplicate rows - [city] is highly overall correlated with [state] and 1 other fields - [state] is highly overall correlated with [city] and 1 other fields - [zip] is highly overall correlated with [city] and 1 other fields - [contact_first] 139 (6.7%) missing values - [email] 71 (3.4%) missing values - [phone] 237 (11.5%) missing values - [zip] 104 (5.0%) missing values - [signup_date] 47 (2.3%) missing values - [monthly_volume] is highly skewed(γ1 = 45.4)

Findings → ingestion rules

Each alert maps to a concrete control before this file joins any warehouse table:

What the profile caughtThe rule it becomes
phone 11.5% missingCompleteness threshold; “phone required” flag for call-campaign consumers.
12 exact + case-variant duplicatesDedup key and entity resolution before joining any merchant dimension.
zip has 4-digit valuesStore as text, zero-pad to 5 on ingest — the classic lost leading zero.
monthly_volume skew γ₁ = 45.4Accepted-range test: negatives (leaked refunds), zeros, and a $1.2B outlier quarantined.
status: active / Active / ACTIVENormalize casing; accepted-values test on the cleaned set.
1900-01-01 and future signup datesFreshness/validity window; sentinel dates rejected at the gate.

Why this matters

The same report runs on every new file drop in CI and gets diffed against the previous profile to catch drift. And because it’s a shareable artifact, the conversation about what “clean enough” means happens around evidence — with stakeholders who never open a notebook.
