The notebook

From calculator to analysis

The raw notebook had the right ingredients: a payment formula, an amortization schedule, and a comparison between a baseline loan and a modified loan with extra payments. The cleaned version makes the assumptions explicit and fixes the variable mismatch in the original notebook, where PRINCIPAL was defined but later cells referenced LOAN_AMOUNT.

Payment formula

The fixed payment comes from the standard amortizing-loan formula. The notebook wraps it in a small function and rounds to cents.

monthly_payment(principal, annual_rate, months) 
def monthly_payment(principal: float, annual_rate: float, months: int) -> float:
    monthly_rate = annual_rate / 12
    if monthly_rate == 0:
        return round(principal / months, 2)

    factor = (1 + monthly_rate) ** months
    payment = principal * monthly_rate * factor / (factor - 1)
    return round(payment, 2)

Schedule engine

Every row tracks interest, scheduled principal, extra principal, ending balance, and cumulative interest. That makes the scenario comparison a simple difference between two schedules.

the monthly loop 
interest = round(balance * monthly_rate, 2)

remaining_after_payment = round(balance - scheduled_principal, 2)

Why this is useful

The point is not the specific loan. The reusable pattern is the side-by-side schedule: model the baseline, model the changed behavior, then quantify the payoff date and interest delta. That structure is easy to reuse for refinancing checks, payment-frequency tests, or different early-principal strategies.
