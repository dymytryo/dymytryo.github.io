The notebook

From calculator to analysis

The raw notebook had the right ingredients: a payment formula, an amortization schedule, and a comparison between a baseline loan and a modified loan with extra payments. The cleaned version makes the assumptions explicit, adds a reusable N-month extra-payment plan, and fixes the variable mismatch in the original notebook, where PRINCIPAL was defined but later cells referenced LOAN_AMOUNT.

Payment formula

The fixed payment comes from the standard amortizing-loan formula. The notebook wraps it in a small function and rounds to cents.

monthly_payment(principal, annual_rate, months) 
def monthly_payment(principal: float, annual_rate: float, months: int) -> float:
    monthly_rate = annual_rate / 12
    if monthly_rate == 0:
        return round(principal / months, 2)

    factor = (1 + monthly_rate) ** months
    payment = principal * monthly_rate * factor / (factor - 1)
    return round(payment, 2)

Schedule engine

Every row tracks interest, scheduled principal, extra principal, ending balance, and cumulative interest. That makes the scenario comparison a simple difference between two schedules.

Flexible extra-payment plan

Instead of hard-coding month 1, month 2, and month 3, the helper below builds any consecutive N-month extra-principal schedule.

recurring_extra_payments(start_date, monthly_amount, number_of_months, start_month) 
def recurring_extra_payments(
    start_date: date,
    monthly_amount: float,
    number_of_months: int,
    start_month: int = 1,
) -> dict[date, float]:
    if start_month <= 0:
        raise ValueError("start_month must be 1 or greater")
    if number_of_months < 0:
        raise ValueError("number_of_months cannot be negative")
    if monthly_amount < 0:
        raise ValueError("monthly_amount cannot be negative")

    return {
        add_months(start_date, start_month - 1 + offset): monthly_amount
        for offset in range(number_of_months)
    }

Why this is useful

The point is not the specific loan. The reusable pattern is the side-by-side schedule: model the baseline, model the changed behavior, then quantify the payoff date and interest delta. That structure is easy to reuse for refinancing checks, payment-frequency tests, or different early-principal strategies.
